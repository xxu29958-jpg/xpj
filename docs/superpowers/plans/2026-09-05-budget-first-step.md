## Outcome and boundaries

A household member setting a month's budget for the first time can fill its total and save without navigating optional rollover, reserves, exclusions and category rows. All those real capabilities remain in the same native form through the existing plan disclosure styling. Existing budgets and rejected forms expose their options immediately, so saved configuration and validation failures are not concealed. Viewer behavior, current month/ledger binding, native/no-JS submission, Budget owner and fresh execution-versus-draft distinction remain unchanged.

Allowed: the production budget template, its existing semantic styling and DOM enhancement, and directly affected behavior tests. Forbidden: financial semantics, new storage/writers, new JavaScript state owner, migration, permission changes or Windows lifecycle work. No decorative asset is added where it would push the first action down; the value here is fewer required decisions and less scrolling. This is an operability improvement within the full consumer-quality wave, not the final visual direction. The user's September 5 photo is a reference, not a prescribed layout; the current direction remains modern consumer software, with final design decisions owned by the main agent.
