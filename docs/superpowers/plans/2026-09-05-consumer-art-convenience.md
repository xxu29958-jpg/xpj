# Consumer art and convenience wave

> Execute with superpowers:executing-plans. The main agent owns production changes; bounded read-only review may run through the requesting-code-review skill. This plan implements the existing full Goal, not a separate product or a new approval gate.

**Goal:** The five work domains feel like one mature household tool, with recognizable art, readable hierarchy and lower effort in first entry, everyday work and recovery.

**Base:** Qualified main `b3408fff332efb5dcbcaf0e80dc81d4edea0a430`; merge the separately qualified external-debt context slice before final integration. Work in the already isolated `xiaopiaojia-clean` checkout, branch `codex/product-art-convenience-20260905`; preserve its untracked `tmp/`.

**Architecture:** Keep the existing modular backend owners, native Web forms, Android state/Room/Outbox, shared semantic appearance and production shells. New art is presentation, never a state owner. No second application, synthetic production data or duplicate current styling stack.

**Tech stack:** Jinja and existing CSS/JavaScript; Kotlin/Compose and existing resources; project-bound raster art only where it improves the actual task.

## Allowed changes and exclusions

- Replace inconsistent decorative state art, hierarchy and copy in real Web and Android consumers. Preserve the receipt/coral-side-clip recognition and reject the green top-clip direction.
- Improve reachable first-entry and recovery actions and reduce redundant controls, preserving native/no-JS and permission behavior where applicable.
- Keep theme, texture, accent and custom-background preferences coherent across the affected screens. Inspect text, focus and long content with the actual background pipeline.
- Capability gaps discovered while doing this remain in the same product atlas. A change to durable publication or identity must be its own bounded vertical task, not smuggled into a visual patch.
- No local PostgreSQL, Android build/emulator, installer or full-suite testing. Cloud executes heavy lanes; local work is source checks and bounded browser visual interaction. No Windows lifecycle operation is opened.
