## 当前实现观察与待取得的反例

以下观察记录开工基线。原生后续实现与证据列在下段，不能把历史观察误读为当前状态。

- 原生账单本体并非没有离线读取：`verifyInitialExpenseFromCache` 已验证当前完整绑定并采用 Room 投影，已接受提交另有 required refresh 保护，本组不得削弱。更正和 offset 提交的原 payload／编号／OCC／身份已由原 Outbox 保留。
- 更正、offset 和 void 的未提交表单存在 `ExpenseFactViewModel` 的会话状态；关闭相应 sheet 会重置，事实页返回会弹出导航项。工厂没有 SavedStateHandle；仅补 SavedStateHandle 也不能覆盖退出详情再重开。基线上的两个实际 JVM 业务反例已失败：关闭更正、另一端改变币种后重开，原原因变为空白；关闭退款、事实包读取失败后重开，原金额文本 ` 0005.50 ` 变为空白。失败已核对 XML，未修改生产代码；后续仍须核准离开详情、Room 冷重开、原提交接受与显式放弃，两个会话用例不能代替完整持久边界。
- `ExpenseCorrectionRepository.fetchRevisions` 直接查询 API；`ExpenseOffsetRepository.fetch` 查询 fact bundle 并发布 root。时间线已有内存失败保留及不可变分页锚，未在这两条读取中发现持久历史快照。不得将内存保留冒充冷启动读取，也不得把账单本体缓存重复算为缺失。
- Web correction 已保留原因、可核对的明细／拆账行和返回上下文，非冲突失败保留原编号／版本；冲突分支会重置标量并采用当前 token。更正页尚未挂载浏览器原稿机制。offset 错误页已有原字段和补汇率续办，但普通错误会轮换编号并采用当前版本；需沿已有 claim／接受结果区分可编辑拒绝与未知结果，不能泛称为全部丢失。
