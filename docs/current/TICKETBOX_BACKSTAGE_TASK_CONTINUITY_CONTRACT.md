# Backstage 配置到原任务结果

## Goal 与当前边界

沿现有识别、AI 建议、汇率和后台任务 owner，核准用户从配置、启用、实际执行到理解结果、失败续办的整组使用。当前基线为 main `9b920823`；实现存在不等于整组资格完成。该组不代替最终 exact Internal Beta RC。

## 已核准的入口与消费者

| 入口与责任 | 必须保留的成功出口 | 待核实的连续性与资格 |
|---|---|---|
| Owner 识别设置 → runtime settings projection → OCR providers | 保存后热生效，关闭自动识别仍可人工录入；本机视觉模型保持 loopback；原件读取沿 digest 和统一 resolver | 实际图片经过真实 provider；关闭/开启、不可达、备用结果及恢复；配置状态不代替实际运行结果 |
| Web/Android 上传 → 原上传 receipt → `expense_enrichment` | 同一原单与持久任务；结果仅形成待人工核对建议，不能改写更新的手工输入或已确认事实 | 离开上传页再找回、原件和原单对应、失败说明、后台/进程中断、原键续办与原 OCC；普通人工录入继续可用 |
| Web 待处理近期识别/任务观察、Android 后台任务/上传观察 | account + ledger 查询；仅已验证且仍可见的原单链接；viewer 读与 writer 取消分开 | 暂时离线保留已读提示；确定失去读取权限撤下旧结果和旧链接；换身份/账本不串结果；恢复后重新读取 |
| Web 原单与抽屉、Android 原单重识别 → `expense_ocr_command_service` | 同一同步命令与 receipt，重试保留原 key/OCC；失败保留原编辑；结果与原稿分开核对 | 两端实际触达和重新进入、ACK 丢失、冲突后明确核对；不把同步重识别说成恢复原后台任务 |
| OCR 后续与原单换算 → `expense_fx` / 原 FX owner | 原币、原始日期、汇率发布日、冻结本位币与人工补率；viewer 可读取本账本原单换算结果 | 实际任务到原单查询、失败与重试、服务重启；后台结果不暗换编辑中的 OCC，显式重新核对后继续 |
| 预算 AI readiness / Owner 同意 / Web 与 Android 请求 → 原 advisor owner | 关闭、未配置、未同意和角色限制；仅允许的汇总输入；建议经人工选择，不能写成预算事实 | 实际请求、失败说明、审计结果、重新进入；可达不代表已授权，测试端点不冒充真实模型质量 |
| Owner 诊断与 Desktop 管理导航 | 配置、安装状态和个人业务结果分层；管理入口不扩大后台任务可见范围 | 从配置到本人原任务的实际导航；Tunnel/健康检查不代替业务结果 |

## Allowed Changes / Forbidden Surface

- 在上述既有 owner 与消费者内修复可执行反例，合并重复读取/恢复责任；复用当前身份、任务持久输入、原单、receipt、Outbox 和查询失权协议。
- 实际 UI 旅程使用隔离安装、合成图片和测试身份；原件摘要、原输入、任务及财务后置条件一并核对。
- 不改日常安装、身份、模型配置、用户数据或离线意图；不新增任务 runtime、第二事实 owner、全局健康引擎或泛化 CI 工程。
- Windows Fresh G2 和现有生命周期 HOLD 保持；完整 restore、升级或重装不在本组。
