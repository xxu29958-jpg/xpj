## 已核准边界与缺口

- 施工前所有提醒都用无目标的同一个 `PendingIntent`，还款采集没有通知出口。#473 已补原任务目标和还款通知出口，尚待最终原生资格；现有预算、固定支出和备份判断继续复用，不重建计算 owner。
- 消费/还款采集当前都是一次在线请求，失败仅释放内存去重。本组显式包括把原采集接入既有 Room/Outbox 的持久接受、身份隔离和恢复；不是只修通知文案，也不增设第二队列。
- 实际消费 mapper 已明确发送 CNY 原币及金额，后端已有 pending FX，保留这项能力；“非 CNY 安装一律拒绝消费采集”是旧注释。还款采集仍只有 legacy home amount，非 CNY 安装被明确拒绝：其原币表达、选债/金额核对及适用查询/导出影响仍待实现和验证。大额提醒仍用固定 50,000 最小单位与人民币阈值文案，非 CNY 本位币的阈值及未定汇率金额解释也纳入本组，不宣称整组只剩验收。
- 还款采集属于本人；欠款投影有自己的读取权限。欠款读取拒绝时撤下目标，不删除本人原采集。身份切换、原确认/忽略意图、迟到回调与持久读取分别核准，不能把缓存投影当成事实或把临时 ViewModel 当成重启恢复。
- 施工前备份持久去重键只有日期；预算/固定支出键有账本但缺完整主体范围。#473 沿既有安装/数据代际/账号/设备身份补足去重与通知目标，凭据不进入通知；当前读取使用既有绑定和权限屏障。
- Android 系统通知为平台出口；Web 继续消费服务端原消费/还款草稿及事实。Owner/Desktop 只承担既有配置和数据安全入口，不新增通知后台或第二业务 App。

## 最小充分资格

1. 小型真实反例：原服务器提醒不能压掉重绑后另一服务器的提醒；同身份同任务仍去重；读取期间换身份不发布；系统拒绝不记已提醒。原采集在断网/未知响应下保留原身份、金额和 key；拒绝或冲突保留可继续处理的原意图。
2. 现有云端 PostgreSQL/Android 资格：适用持久命令、读取拒绝、并发/幂等/OCC、旧 writer 退役、消费者与构建检查。新类型继续由原 Outbox 调度、失败和回执机制承担，不放宽门禁。
3. 实际隔离模拟器 + Web + PG 旅程：开关/授权 → 合成白名单通知或新鲜业务判断 → 真系统通知点击 → 原任务 → 人工核对/失败恢复 → 财务、去重及原输入后置条件。覆盖冷/热启动、重启、两条并存通知、切主体/账本、渠道关闭恢复和返回未完成编辑/分享；明暗主题和窄屏核对真实页面。
