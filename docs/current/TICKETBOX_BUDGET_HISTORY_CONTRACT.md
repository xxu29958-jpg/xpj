## 用户结果与责任

- Web 月度预算与 Android 预算页均可打开当前月份的修改记录，逐页回看建立、修改、归档和恢复。
- 每条记录保存当时的币种、总额度、结转、非月度预留、排除分类及分类额度；显示当时安排，不将今天的执行额伪装成历史执行额。
- 旧预算在迁移时只形成一条明确标注的已有快照。不编造创建人、旧修改或修改时间；旧币种未记录时保持未知单位，不按当前币种重新解释。
- `Budget`/`BudgetCategory` 继续由原预算保存、归档和恢复命令拥有。`BudgetRevision` 是同一事务内的不可变记录，按该预算的 OCC 版本唯一；已有幂等命中返回原回执，不新增记录。
- 冲突或历史写入失败不能留下预算、分类和历史不一致的部分提交。读取不写库；权限与账本作用域沿现有鉴权。
- API 与 Web 复用同一历史查询，按版本游标分页。Android 通过 Repository 和完整逻辑绑定读取；家庭更换或读权限被拒绝时清掉旧显示，网络失败保留已读记录并可重试。
- 已归档预算仍能回看历史，原回收站恢复行为保留。完整数据出口包含全部授权预算记录，不受页面分页限制。

## 保留与边界

预算总额/分类编辑、真实执行投影、币种、防旧表单覆盖、Room/Outbox、原 key/body/OCC、归档恢复继续有效；没有替换这些入口、writer 或队列。本片消除的是“保存后只有最后值”的缺口。

不改变目标、收入或固定支出的历史规则，不将预算安排变成实际支出/存款，不执行日常数据迁移或安装。Windows Fresh G2 与既定 HOLD 保持。目标/series 历史、持久储蓄安排、Budget/Debt 冷启动离线读取仍在总产品地图中继续施工，不作为本片合并前置条件。

## 验证与完成边界

- 窄序列化/页面测试：原币金额、分类替换后的不可变快照、未知币种、历史空态、文案与转义。
- PostgreSQL/API：保存→修改→原键重放、OCC 拒绝、历史失败的事务回滚、归档恢复、viewer、账本隔离、不可变约束。
- Alembic：已有快照与分类/归档保留、允许无新增历史时 round trip；有真实修订时拒绝擦除式降级。
- Portable：授权范围内历史完整导出，另一账本不进入结果。
- Android：绑定更换和延迟旧响应、分页失败重试、读取拒绝；实际 BudgetRoute 打开历史、原 JPY 分类金额及翻页且不产生写命令。
