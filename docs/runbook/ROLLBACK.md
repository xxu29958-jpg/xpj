# 版本回退与现场保留

当前已安装 Windows 没有完整数据集恢复或二进制/schema 降级入口。本文说明源码验证、Android 旧版回归和配置恢复的边界，不提供手工覆盖已安装数据的回退程序。

## 当前支持边界

| 对象 | 当前处理方式 |
|---|---|
| 源码/测试后端 | 保留当前工作树和失败现场；在与目标代码匹配的可弃验证环境、隔离数据库中重新建立测试夹具 |
| 已安装 Windows | 完整恢复、既有安装升级/降级、保留数据 repair/reinstall 继续 `QUALIFIED_HOLD`；不能用旧源码命令绕过安装和数据身份 |
| Android 旧版回归 | 使用隔离测试设备或模拟器及一次性后端；同一 minor 不代表数据库、草稿、Outbox 和绑定一定向下兼容 |
| 公网域名与 Tunnel 配置 | 保留当前配置，通过现行配置入口恢复目标域名/路由并验证实际连通；不改数据库或安装身份 |

## 源码/测试环境

1. 记录目标代码版本、当前 schema、测试实例归属及失败日志，保留未提交改动和仍需调查的现场。
2. 结束本次源码后端和测试任务；只对已核实属于该测试环境的进程、数据库执行停止或重建，不操作日常 Windows 服务。
3. 在与目标代码匹配的可弃环境中，按 [本机 PostgreSQL 验证边界](postgres-local-safety.md) 准备专属实例，显式将 `DATABASE_URL` 绑定到生成的测试地址。
4. 使用目标代码的现行迁移和夹具建立测试事实，再执行受影响的真实用户流程。原现场需要保留时，使用另一个独立测试环境，不能复用会被重置的 smoke 库。

旧 complete-dataset/restore 原型及其 scratch 演练已退役，当前没有 `pg_restore` 回退操作步骤。不要根据旧版本不读取某些表就手工删表，也不要把新 schema 直接交给旧二进制。需要保留同一数据集的回退，不属于上述可弃测试流程，须由后续受管生命周期能力承接。

## 已安装数据的保护

现行有界冷备、只读库存及完整恢复限制见 [PostgreSQL 运行与验证边界](POSTGRES_MIGRATION.md) 和 [备份任务边界](WINDOWS_BACKUP_TASK.md)。冷备可读和原件 hash 一致，不等于原安装可恢复、异机接管或旧版本可启动。

产品内 CSV 导出只覆盖导出范围内的已确认流水；可携带账本包可包含历史、关系和原件。两类业务出口都不包含完整 PostgreSQL 集群、宿主凭据、安装绑定或设备未提交意图，不能用于承诺完整回退。已安装数据不得交给源码测试重置、手工灌库或旧生命周期入口。

## Android 版本回归

卸载或清数据会丢掉设备本地状态，不能作为保数据回退步骤。后端已确认事实的同步不能恢复尚未提交的草稿、Outbox 意图或设备绑定。

旧 APK 的调查应在隔离测试设备/模拟器上进行，并使用对应测试后端和现行绑定入口。日常设备更新须另行核对签名、版本兼容和本地数据保留；没有相应资格时，不宣称“同一 minor 始终可逆”或要求用户卸载重装。构建入口见 [RELEASE_PACKAGING.md](RELEASE_PACKAGING.md)。

## 配置恢复与结果核对

Tunnel 只处理网络入口，参见 [CLOUDFLARE_TUNNEL.md](CLOUDFLARE_TUNNEL.md)。恢复后分别核对本机后端与外部实际消费者；本机健康成功不能代替外部连通。

验证须同时说明实际代码/产物版本、使用的数据环境、原件与财务结果、失败后的可续办状态。版本字符串、服务启动或页面可访问不能单独证明回退成功。完整 Windows 恢复/降级资格仍在后续生命周期阶段，不由本文或源码检查开放。
