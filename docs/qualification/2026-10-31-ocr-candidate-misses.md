# 保存时的候选缺口（W4）

成功保存的金额、商户、时间不在该原件候选中时，记录候选缺口和字面文字是否存在。明确的原文纠正附在原有事件上；没有原文纠正的普通修改仅记诊断，`_learning_qualified=false`，沿用现有资格门拒绝其进入运行记忆和 W1 合格语料。原有 source correction 的资格和历史备选行为不变；缺口元数据不增加另一份支持票。

门禁：真实 API 覆盖三个字段的无候选保存、幂等重放和重复保存；同一个字面缺口的原文纠正/普通修改资格不同；撤回、来源失效不改变财务值；数据库回滚同时撤销保存和缺口事件。现有金额、时间、原文纠正消费者回归须通过。仅既有成功 save 事务写财务值，不增加表、接口或 G3 入口。

普通诊断采用既有事件保留策略。时间字面诊断只检查明确的日期/钟面分量，不把它当作时区、区域或交易归属证明；未知上下文保留 unknown。留出集不参与此功能验证。

已确认账目的时间更正继续仅作诊断；本次没有为它新增原文纠正入口。待确认保存中已有的时间选择仍按原资格规则处理。

验证：新增 7 项真实保存、幂等、撤回、冲正与回滚场景以及 10 项字面诊断契约通过；49 项既有字段/时间选择和 19 项原文反馈回归通过。错误来源 ID 或旧解析器选择仅留下绑定当前原件的普通诊断，不能制造合格纠错。
