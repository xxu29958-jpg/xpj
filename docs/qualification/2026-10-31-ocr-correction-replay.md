# 纠错标签只读回归（W1）

在干净的候选版本中，从 `backend` 运行：

```text
python -m scripts.ocr_correction_replay --tenant-id owner --actor-account-id 1 --output LOCAL_PRIVATE_REPORT.json
```

连接地址通过环境变量 `XPJ_CORRECTION_REPLAY_DATABASE_URL` 提供。输出必须是新文件；原图、原始文字、标签值不会写入报告。报告包含本地标签/证据标识，仍应留在安装所有者控制的本地目录，不能提交仓库。

工具以 PostgreSQL `REPEATABLE READ, READ ONLY` 事务读取当前成员的字段/时间选择事件，沿用现有资格判断；撤回、隔离、过期、来源变化和采纳污染的事件排除并计数。无标签数上限。通知证据没有相应图片事实时归入 unbindable，不升级成人工图片标签。未明确附着字段的原文转写属于另一评测合同，不混入字段纠错分母。

新 OCR 事实冻结 parser 的币种、小数位、时区和参考时间。旧事实只从已存候选恢复唯一钱币上下文及已存来源时区；缺失时不借用当前账单或设置。只重放已存文字和块，不重新识图，不创建事实、决策或学习事件。

绑定要求字段、值、币种一致，并且同图同坐标空间的每个标签框都能与新候选框重叠（IoU ≥ 0.5）。候选 ID 改变不会丢失绑定；别处出现同金额不算成功。结果：

- `same`：新旧候选均能绑定，或均不能绑定；后者明确标为仍无等值候选。
- `fixed` / `broken`：新版本恢复 / 丢失原区域的等值候选。
- `unbindable`：标签缺少可靠位置、冻结输入或证据无效；保留在合格标签总分母。

是否成为默认选择另记 `baseline_selected` / `candidate_selected` 及汇总增退，避免把“还能找到”当成“仍然选对”。报告记录 Git commit/tree 和重放源码摘要。

本地 9 项新增测试覆盖金额/商户/时间、ID 变化、重复金额异位、修复与丢失、旧上下文、默认时区改变后的冻结输入、撤回/隔离、账本/成员过滤、账务行及版本指纹不变，并真实执行写入被 PostgreSQL 拒绝。另有 67 项现有 OCR/时间证据测试通过。此证据证明工具行为，不代表真实用户纠错集质量收益。
