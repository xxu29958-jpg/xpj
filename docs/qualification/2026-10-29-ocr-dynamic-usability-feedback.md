# OCR 动态调度、可用性与反馈专项

范围权威为用户指定的[完整方案](https://chatgpt.com/space/page_3ead8cb265408191bae986ec5587d8c6)第 1–412 行，2026-10-29 核对 sequence 3。启动基线 `c67594104ebd3f2a9be4ddf0adac9f65fca75af7`。本记录不代替完整方案，也不宣布全专项退出。

- **Goal**：可靠保留原图和主识别结果，点选/直输完成纠错，在既有单槽与 PG task owner 上有界接纳、恢复和调度，让合格反馈通过真实后续消费者发挥作用。
- **Allowed Changes**：现有 provider 编排、原件/任务/回执 owner、Android/Web 核对与草稿恢复、反馈资格/撤回/记忆、现有图片基准和受影响发行件。
- **Forbidden Surface**：第二队列、图片库或学习权威；自动改写已确认事实；覆盖 WIP、日常身份/数据、历史通过/失败证据；苹果延期与 R2/U1/C1 HOLD 不扩入本专项。
- **Done Checks**：方案五片全部结果及失败/恢复反例；Android/Web 实际核对旅程；Windows 原生资源与端到端时延对照；来源可核验的真实图片和独立反馈消费，含撤回后对照；最终 exact source/tree/发行件/schema 的适用门禁和唯一交接。
- **Evidence**：每片保留命令、主体和通过/失败/未执行/阻塞记录。模拟 provider 只证明编排与事务，图片 provider 才能证明识别；自动脚本用时不等于用户用时，缺少独立真值不报告准确率提升。

## 施工顺序

1. 主结果保留与真实部分结果状态。
2. 点选/直输核对和分型的人工原件反馈。
3. 持久接纳额度与执行预算分离，原任务自动有界续办。
4. 单槽交互优先、公平/老化、跨入口资源准入和测量后调节。
5. 真实反馈消费、独立回放与整个专项的受影响消费者/发行件验证。

## 第一片：备用增强不能丢弃主结果

调用链仍为上传原事务 → `expense_enrichment` → `collect_auto_ocr_extractions` → Expense owner 的短 OCC 事务 → OcrFact + 原任务 applied receipt → Web/Android 观察者。没有新增队列、schema 或财务写入口。

主 provider 的失败和备用增强的失败分开处理。主结果有文字而增强失败时提交主结果，并在同一回执记录 `enhancement_failed`；没有任何可用结果时保留失败语义，不伪造成功预测。`ocr_attempts.elapsed_ms` 是该次 provider 调用的耗时（可能包含排队/加载/推理），不能当作纯推理或端到端耗时。

跨 provider 的 confidence 不再作为替换依据。只在原有确定性解析的已知字段全部保持、且新增缺失证据时采用增强结果；金额/币种、时间角色/精度、商户或领域解释不一致时保留主结果并提示 `provider_conflict`。两份预测仍追加保存，只由一份完整的选中结果提供草稿，避免跨预测拼装交易。选中结果最后追加，继续使用现有最新有效 OcrFact 读取权威。

Web 原任务提示、近期上传、批量上传终态和 Android mapper/观察者/状态带共同消费这两个提示。普通保存、OCC、取消、撤权、原图摘要、已应用回执与 FX 续办保持原 owner。原始失败和人工修改不会被“增强成功”覆盖。

回退只恢复原编排与展示代码；无 schema 逆迁移。已经保存的财务值、预测和回执保留。旧消费者忽略新增回执字段时仍按原 `outcome` 读取，不能把这种兼容性称为已展示新的核对提示。

本片的定向验证覆盖 provider 超时/冲突/全失败、原子提交与重复执行、丢提交回执、取消/撤权/OCC/原件变化，以及 Web 上传到提示和 Android 状态消费。模拟 provider 的断言不构成真实图片收益或 Windows 性能结论。最终资格须在剩余切片完成后绑定实际候选。

本地实际验证（2026-10-29）：普通 lane 的 OCR 编排/内部解析、Web 近期识别/上传和上传契约 85 项通过；串行 real-db lane 的 worker/任务/缩略图事务 31 项通过；Web 真实上传至提示、部分结果原子提交和全失败 7 项通过。复核修正“空结果不构成矛盾”后，provider 边界 11 项通过。各集合有重叠，不相加声称独立用例总数。Android 三个受影响测试类 16 项通过，`detektGrayDebug` 与 `detektGrayDebugUnitTest` 均零 finding；受影响 Python Ruff 与 diff 格式检查通过。

上述验证是本地编排/事务/消费者模型证据，尚未执行本片发行件、Windows 图片性能和设备操作旅程；后续切片及最终候选门禁补齐适用验证。pytest 报告了已有临时目录 ACL 清理警告，不涉及本片产品断言失败。

PR #700 审查发现并复现：增强文字中的金额和它返回的结构化金额矛盾时，既有合并规则会弃用金额，不能只比较解析候选就声称主金额已保留。比较现在同时包含合并后实际可用的值；新增 provider 反例与同一真实事务/回执回放验证。候选 ID 不替代实际可写入值。

第二条审查反例覆盖商品行：增强结果补出时间却省略主识别明细时，仍保留主结果；明细的名称、数量、单价、金额、类别与类型也纳入比较。明细冲突提示核对，完整保留明细后才允许新增缺失字段。真实数据库回归核验最终草稿的两条明细与重复执行不增写。

## 第二片 A：浏览优先与两点选框

沿用 Android `OcrRegionPicker` 和 Web `ocr-region.js` 的原图、坐标转换与原识别意图，默认进入浏览模式。需要局部重读时可点两个对角，仍可选择拖动选框；第一点用原图坐标保留，放大或平移后再点另一角不会混用屏幕坐标。Android 控件允许换行、对话框可滚动，返回保留账目草稿。局部重读仍是明确的识别命令，本片没有把选框改作人工文字标签。

本地 Web 实际浏览器/PG 恢复路径 4 项通过，包含默认浏览不建选框、两点之间缩放、最终原图坐标、丢回执续办、错误区域重新调整与财务草稿保留。Android instrumentation 源已编译；必需的两个 typed Detekt 和 lint 通过。额外运行的 `detektGrayDebugAndroidTest` 报告 95 项 finding，属于未通过的额外扫描，未按本片通过处理；该任务不是仓库 CI 的必需 typed Detekt 门禁。Android 实际 Connected 运行等待本片 exact-head CI；脚本操作不能充当真实用户用时。

候选来源联动、无候选人工原件反馈及其后续消费仍在第二片后续切片中实现，本片不代表整个核对/反馈范围完成。

## 第二片 B：候选对应的原图位置

字段与时间候选可携带来源位置。投影只使用原 OcrFact 中与候选原文跨度完全对应的文字框，并携带原图 SHA、经 EXIF 转正后的像素尺寸与坐标系；金额相同不能据此建立关联。历史文字与框不对应、越界、无框或通知来源均不生成位置。Android/Web 从现有受保护原图入口读取实际图片，再核对摘要及尺寸；不一致时允许返回手填，不高亮错误原件。

点“看原图这一处”自动定位对应文字框，可放大浏览并切到上一处/下一处。Android 复用原 `OcrRegionPicker` 的显示、平移和坐标转换；Web 复用原图 HTTP 快照。打开、浏览与返回不会改动财务草稿或形成反馈标签。原图加载失败与正在加载分别展示。没有新增图片存储、财务写入口或 schema。

本地位置投影 7 项反例通过；现有字段选择 19 项在相同生产修改下通过。Web 实际浏览器/PG 三条旅程覆盖窄屏完整页、EXIF 旋转抽屉、旧 SHA 拒绝高亮；手填 22.00 在返回后确认入账，且不新增字段或时间学习事件。截图检查曾发现抽屉缺少样式与完整页背景透明，已修复并新增可见图层对齐、弹窗边界断言；失败证据保留。Android instrumentation 已编译，两个必需 typed Detekt 零 finding；实际 Connected 旅程仍待此片 exact-head CI，不以编译代替执行。

后续仍需字段就近整行选择、无候选人工原件反馈和资格/撤回/真实后续消费。本片位置展示不代表视觉标签已取得资格，也不证明 OCR 准确率或用户操作用时改善。

## 第二片 D：没有候选也能保留人工原文

Android/Web 的金额、商户、时间旁增加可选原文反馈。只展开或浏览不提交标签；普通账目保存不要求定位。文字、字段角色和读不清/裁切/未出现各自显式记录；定位默认浏览，可跳过、点一个大致位置，或用两个角点指定范围。原文输入不改财务值，退出定位与恢复草稿保留原输入。反馈通过原有保存/确认命令、幂等键和离线 outbox 提交，没有增加独立提交端点、图片库或 schema。

后端在同一财务事务中核对原图 SHA、EXIF 转正后的尺寸、范围和可选旧预测归属；使用既有 LedgerLearningEvent 保存独立的 original_text_feedback，不伪造候选或 OcrFact。只有文字与精确范围都明确核验的记录才取得视觉转写资格；其余保留诊断用途。后续财务更正或新 OCR 不抹掉人工原文；原图变化、移除、同字段后继反馈和撤回按既有资格 owner 处理。保存成功回执才说明反馈已保留，排队待提交不冒称服务端已保存。

## 第三片 A：持久接纳额度与原成功回执

当前代码已有原图、Pending、任务输入和原幂等回执的共同提交边界；默认 8 项持久任务额度独立于执行池 2 项、其中 OCR 1 项的运行额度。这些既有责任继续复用。扩展同一 PostgreSQL 接纳锁，核对每账本数量、待处理原件总字节与账本字节；同一原件被多个任务引用只计一次，仍从既有附件路径与租户 resolver 读取实物大小，不增加配额表、队列或图片副本。

默认总任务 8、每账本 8、待处理图片总计 64 MiB、每账本 32 MiB；对应配置为 BACKGROUND_TASK_MAX_ACTIVE、BACKGROUND_TASK_MAX_LEDGER_ACTIVE、BACKGROUND_TASK_MAX_IMAGE_BYTES、BACKGROUND_TASK_MAX_LEDGER_IMAGE_BYTES。UPLOAD_MIN_FREE_BYTES 默认 512 MiB，在原件发布前及上传接纳时检查磁盘余量。这些是可配置的接纳上限，不是性能测量结论。拒绝时保留客户端原图/原键，文件、账单、任务和未成功幂等 claim 一起补偿；HTTP 507 存储不足沿 Android/Web 原失败出口暂停后续上传。

已成功接纳的原请求不因重启续办额度满而返回“尚未保存”：原成功回执仍原样返回，原识别任务保留等待续办。新上传超过额度仍明确拒绝。原图和任务没有因为重复点击产生第二份持久事实。

本地 serial real-db lane 51 项通过，覆盖新数量/字节/账本/磁盘额度、两运行任务下仍可接纳等待项、原键恢复、提交歧义、取消、OCC、权限及原有 FX 接棒。ordinary lane 89 项通过，覆盖原件补回、上传格式与其余相关边界；两个 lane 分别记录，不把未选择测试记为通过。Android 上传分发单测和两个必需 typed Detekt 通过，错误码三端文案审计与 Ruff 通过。此片不声称实际线程压力测量或自动恢复完成；有界扫描/退避、调度与最终发行件资格仍待后续。
