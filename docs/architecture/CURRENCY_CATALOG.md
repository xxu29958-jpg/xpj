# Currency catalog

`backend/app/currency_catalog.py` is the explicit money metadata owner. Its 153 circulating codes and Chinese names were checked on 2026-10-14 against [Unicode CLDR](https://github.com/unicode-org/cldr/tree/main/common) validity and Chinese locale data. Minor-unit exponents follow ISO 4217, cross-checked with [OpenJDK CurrencyData.properties](https://github.com/openjdk/jdk/blob/master/src/java.base/share/data/currency/CurrencyData.properties); [SIX](https://www.six-group.com/en/products-services/financial-information/market-reference-data/data-standards.html) maintains the ISO currency standard. Cash rounding and locale presentation do not define stored minor units. Metals, funds and test codes are excluded.

Run `python backend/scripts/sync_currency_catalog.py` after an intentional catalog change; `--check` verifies Android's offline copy. Database constraints use a frozen migration snapshot. Existing currencies keep their original exponents, and changes to those exponents require an explicit data-contract decision rather than display-only relabeling.

Currency selection and automatic quote coverage are separate. New installations use the key-free [Frankfurter V2](https://frankfurter.dev/) reference source. Existing configured V1/ECB sources remain configured; V2 stores `source=frankfurter`, while the legacy ECB mirror retains `source=ecb`. V2 requests direct pairs to the chosen home currency and keeps each pair's provider date. Dated fetches can extend historical coverage only through a closed UTC date. Manual overrides and frozen financial snapshots keep their existing precedence and immutability.
